# Model Card

## Общая информация

**Название модели:**  
mDeBERTa-v3-base-xnli-multilingual-nli-2mil7

**Источник:**  
[Hugging Face Hub](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7)

**Автор / организация:**  
Moritz Laurer (MoritzLaurer). Базовая модель mDeBERTa-v3-base предобучена
Microsoft на многоязычном корпусе CC100.

**Задача модели:**  
Natural Language Inference (NLI) и zero-shot классификация текста: модель
относит текст к категориям, названия которых передаются вместе с запросом,
без дообучения на этих категориях.

**Язык:**  
Многоязычная модель. Дообучена на 27 языках, включая русский (`ru`) и
английский. По заявлению авторов, может работать примерно со 100 языками
базовой модели.

**Лицензия:**  
MIT.

## Использование в проекте

Модель выполняет шаг 4 сценария
[UC-01](../project/requirements.md#uc-01):
определяет категорию обращения в техническую поддержку.

1. Пользователь отправляет обращение через `POST /requests`
   (см. [Документация API](../api/index.md)).
2. Система сохраняет обращение и передаёт его текст модели вместе с четырьмя
   категориями. Соответствие названий и кодов API:

   | Название для модели | Код в API (`classification.category`) |
   |---------------------|---------------------------------------|
   | «Оплата»            | `payment`                             |
   | «Доступ»            | `access`                              |
   | «Ошибка»            | `error`                               |
   | «Вопрос»            | `question`                            |

3. Модель возвращает оценку для каждой категории. Категория с наибольшей
   оценкой сохраняется в `classification.category` (код из таблицы выше),
   её оценка — в `classification.confidence`.
4. Если `confidence` ниже порога или модель недоступна, обращение попадает
   в общую очередь со статусом `needs_manual_classification`, и категорию
   назначает оператор (US-03).

Zero-shot режим позволяет запустить сервис до того, как накоплена история
размеченных обращений. Ручные назначения категорий операторами (флаг
`manuallyAssigned`) в дальнейшем можно использовать для дообучения модели.

## Входные данные

- текст обращения (до 5000 символов, ограничение API);
- список названий категорий-кандидатов;
- шаблон гипотезы, например: «Это обращение про {}.»

Внутри модель получает пары «текст обращения — гипотеза» для каждой категории.

## Выходные данные

Для zero-shot классификации — список категорий, отсортированный по убыванию
оценки, и оценка (score) для каждой категории. При `multi_label=False`
оценки в сумме дают 1.

Для NLI — вероятности трёх классов: `entailment`, `neutral`, `contradiction`.

## Метрики качества

Авторы указывают accuracy на тестовой выборке XNLI (5010 текстов на язык):

| Язык         | Accuracy |
|--------------|----------|
| Русский (ru) | 0.803    |
| Английский   | 0.871    |
| Немецкий     | 0.824    |

На английских наборах: MNLI — 0.857, ANLI — 0.537, Fever-NLI — 0.761.

Это метрики задачи NLI, а не классификации обращений. Метрики на данных,
похожих на обращения в поддержку, не указаны авторами модели.

## Ограничения

**Указано авторами модели:**

1. Основной обучающий датасет создан машинным переводом с английского, что
   снижает качество данных для сложной задачи NLI.
2. Возможные смещения нужно смотреть в статье DeBERTa-V3 и в литературе по
   использованным NLI-датасетам. Отдельного анализа bias авторы не приводят.
3. mDeBERTa не поддерживает FP16, на старых версиях Transformers возможны
   проблемы с токенизатором (рекомендуется версия 4.13 или выше).

**Потенциальные ограничения для нашего проекта:**

4. Модель не обучалась на обращениях в поддержку. Качество на нашей задаче
   может быть ниже метрик XNLI, его нужно измерить на размеченной выборке.
5. Короткие и общие обращения («Ничего не работает») могут получать близкие
   оценки по нескольким категориям.
6. Максимальная длина входа не указана авторами модели. В примере кода
   используется `truncation=True`, поэтому конец длинного обращения может
   быть отброшен.
7. Результат зависит от формулировок категорий и шаблона гипотезы, их нужно
   подбирать и проверять.

## Не рекомендуется использовать

Раздела об использовании не по назначению в карточке модели нет. Для нашего
проекта не рекомендуется:

- принимать решения без участия оператора, если уверенность модели низкая;
- использовать модель для блокировки пользователей, оценки сотрудников или
  других решений, влияющих на права людей;
- использовать оценку `confidence` как гарантию правильности категории.
