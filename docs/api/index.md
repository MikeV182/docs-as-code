# Документация API

API позволяет внешним системам отправлять обращения в техническую поддержку,
получать результат классификации и назначать категорию вручную.

Спецификация в формате OpenAPI 3.0: [openapi.yaml](openapi.yaml).

## Endpoints

| Метод | Путь                      | Назначение                                | Требование   |
|-------|---------------------------|-------------------------------------------|--------------|
| POST  | `/requests`               | Отправить обращение на классификацию      | US-01, US-02 |
| GET   | `/requests/{id}`          | Получить обращение и результат            | US-02        |
| PUT   | `/requests/{id}/category` | Исправить или назначить категорию вручную | US-03        |
| GET   | `/categories`             | Получить список категорий                 | —            |

## Ошибки

Все ошибки возвращаются в едином формате:

```json
{ "code": "VALIDATION_ERROR", "message": "Опишите проблему" }
```

| HTTP-код | `code`             | Когда возникает                                  |
|----------|--------------------|--------------------------------------------------|
| 400      | `EMPTY_TEXT`       | Передан пустой текст обращения                   |
| 400      | `TEXT_TOO_LONG`    | Текст обращения длиннее 5000 символов            |
| 400      | `VALIDATION_ERROR` | Передана неизвестная категория                   |
| 404      | `NOT_FOUND`        | Обращение с указанным номером не найдено         |
| 500      | `INTERNAL_ERROR`   | Внутренняя ошибка сервера                        |

Если ML-модель недоступна, обращение всё равно создаётся (код 201) и попадает
в общую очередь: `status = needs_manual_classification`, `classification = null`.
